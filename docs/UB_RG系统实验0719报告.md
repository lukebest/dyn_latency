## 3. Sys1：串行 Wide-EP（step 与 throughput）

**设计（§4.3.1）**：Wide-EP 同构部署；同一 microbatch 上 `Attn → Dispatch → FFN → Combine` **严格串行**，通讯与计算不重叠。主观测：step 时延与 per-device throughput（$B/T_{\mathrm{step}}$）。本报告范围：场景1；方案 `packet_spray` / `ub_rg`。

**本轮矩阵**：B∈{16, 64, 256} 均扫 Zipf S∈{0, 0.5, 0.9}（EP=128、L=60）；另含 EP=64 与 L∈{32, 94} 单点对照（默认 S=0.5）。实收 summary **24** 个。

## 4. Sys2：Wide-EP TBO（m、speedup 与掩盖）

**设计（§4.3.2）**：仍为 Wide-EP；全局 batch 切成 m 个 microbatch，计算/通讯双 stream 做 TBO ping-pong，期望通讯被计算掩盖。主配置 m=2；对照 m=1（退化为不掩盖）与 m=4。每 MB 网络时延取自 batch=$B/m$ 的逐包 Dispatch/Combine CCT，并在 L 层上对每个 MB 各用一次。

**本轮矩阵**：场景1、B=256、EP=128、L=60；m∈{1, 2, 4} × S∈{0, 0.5, 0.9} × {`packet_spray`, `ub_rg`}。实收 summary **18** 个。

**本轮结论**：

- Packet Spray、S=0.5：m=2/m=4 相对 m=1 为 1.56× / 2.06×（mask：29.8% 通讯重叠 / 78.7% 通讯重叠）。加速主要来自更小 MB 的 CCT 下降；本矩阵未做因素消融。

- 高倾斜下掩盖变难：Spray S=0.9 时 m=2 相对 m=1 仅 1.94×（mask：8.5% 通讯重叠）。

- `ub_rg`、S=0.5：m=2/m=4 speedup 为 1.30× / 1.27×；通讯利用率≈1，计算几乎藏不住通讯（mask≈0）。

- `ub_rg`、S=0（已补齐 m=1/2/4）：speedup=1.41× / 0.71×；均匀流量下切 MB 同样放大总 RG 通讯，m 越大越差。

## 5. Sys3：AFD（M:N、Tc、双向掩盖率与 throughput）

**设计（§4.3.3）**：AFD 角色分离——M 个 Attention NPU 与 N 个 FFN NPU；层边界为非对称 M2N Dispatch / N2M Combine，再叠 m-microbatch ping-pong。网络侧测 $T_c=\max(T_{\mathrm{M2N}}, T_{\mathrm{N2M}})$，$T_f=\max(T_a,T_e)$。双向掩盖条件为 $m T_f \ge 2(T_f+T_c)$；表中**双向掩盖率**=$m T_f / 2(T_f+T_c)$（≥100% 为通过）。场景1 主推荐 7:1（M:N=112:16），对照 1:1 与 31:1。

**本轮矩阵**：场景1、B=256、L=60、placement=`role_packed`；7:1 为 m∈{1,2,4}×S∈{0,0.5,1} 全网格；1:1 与 31:1（exposed）在 m=2 上扫 S∈{0,0.5,1}；两方案 `packet_spray` / `ub_rg`。实收 summary **30** 个。

**本轮结论**：

- 双向掩盖率：0/30 个样本 ≥100%（通过）；本轮最小/中位/最大为 0.90% / 16.69% / 73.44%。未通过时表中直接给出该比率（越小说明 $T_c$ 相对 $T_f$ 越大）。

- 7:1、m=2、S=0.5：Spray Tc=994.7 µs、step=11285.2 µs；`ub_rg` Tc=386.0 µs、step=10067.7 µs。倾斜负载下 `ub_rg` 的 AFD Tc/step 更低。

- `ub_rg` 在均匀专家（S=0、7:1、m=2）Tc=283.4 µs，远低于同结构 S=0.5 的 386.0 µs；RG 对热点更敏感。

- 1:1 对照（m=2、S=0.5）`ub_rg` Tc=155.8 µs，双向掩盖率 33.1%；逐包证据不支持“本 fabric 上 m=2 可无条件隐藏 AFD 双向通信”。

- Tc 口径为单 seed 方向 CCT 的 max，不是跨 seed CCT-P99；不用逐 token latency 替代。
